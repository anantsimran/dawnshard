ML infrastructure, designed top-down

Dawnshard

Most ML code grows bottom-up: a script becomes a notebook becomes a tangle of globals. Dawnshard goes the other way, with clean seams between configuration, state, and computation, and it's engineered like a real codebase.

The long-term goal is Constitutional AI and RLHF. The training loop, observability, and reproducibility primitives here are the groundwork.

Design choices

Every seam is deliberate

Each choice below trades a little convenience for code you can reason about, test, and reproduce. The full reasoning is in the README further down.

{% include ".icons/material/function-variant.svg" %}

No Trainer god-class

State (TrainState), policy (EpochSpec), and mechanism (fit, run_epoch) are kept apart: separation of policy and mechanism, plus explicit state as in JAX and Flax. Nothing hides in self.

{% include ".icons/material/swap-horizontal-circle-outline.svg" %}

One loop for train and eval

run_epoch takes the step function as an argument, so the same code drives training and evaluation. Metrics are injected as a type and three functions, so adding one never touches the loop.

{% include ".icons/material/source-commit.svg" %}

Every run is reproducible

Each run writes a history file with its git commit, the optimizer's hyperparameters, and per-epoch metrics, duration, CPU, RAM, and GPU memory. Any result can be traced back, and any two runs can be compared.

{% include ".icons/material/ruler-square.svg" %}

Shapes checked at runtime

Every forward() is annotated with jaxtyping and enforced by beartype. A shape mismatch fails at the call site, not as a cryptic error three layers downstream.

{% include ".icons/material/chart-timeline-variant.svg" %}

Observability built in

loguru for humans, a history JSON for machines, probes that look inside the model mid-run, optional Weights & Biases, and Chrome profiler traces from profiled_fit. None of it is bolted on later.

{% include ".icons/material/hammer-wrench.svg" %}

Engineered like a codebase

uv for dependencies, Docker for prod/dev parity, keyword arguments enforced by a custom linter, and make precheck before every PR.
