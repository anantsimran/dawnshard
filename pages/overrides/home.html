PyTorch training infrastructure

Dawnshard

A top-down–designed ML infrastructure library.

State, policy, and mechanism are three separate objects. TrainState holds the model and optimizer, EpochSpec decides how batches are scored and observed, FitConfig sets the epochs, seeds, and early stopping, and fit runs the epochs. A CNN and a transformer go through the same fit, and the loop's package imports neither.

train_state = TrainState(
    model=model.to(device=DEVICE),
    optimizer=torch.optim.Adam(params=model.parameters(), lr=1e-3),
    criterion=nn.CrossEntropyLoss(),
)
epoch_spec = EpochSpec(
    device=DEVICE,
    metrics_type=ClassificationMetrics,
    calculate_metrics=calculate_metrics,
    accumulate_metrics=accumulate_metrics,
    reduce_metrics=reduce_metrics,

history = fit(

Design choices

Separate responsibilities in the code

The loop receives its state, scoring, and data as arguments. Package tests keep the dependency boundaries in place.

01 / Architecture

Separate state, policy, and mechanism

Replace a model through TrainState or change metrics through EpochSpec. fit reads both, plus a FitConfig for epochs and seeds, without importing a model or dataset.

Trace the separation {% include ".icons/material/arrow-right.svg" %}
02 / Comparison

Give no class two jobs

Keras, Lightning, and Hugging Face each let one class hold several concerns. Here a new loss, metric, or probe is an argument, and every model stays a plain nn.Module.

Compare the trainers {% include ".icons/material/arrow-right.svg" %}
03 / Extension

Give each concern one home

Metrics score outputs, probes inspect a batch, and checkpointing stays a named function. A new concern has a clear place to enter.

Find the extension points {% include ".icons/material/arrow-right.svg" %}
04 / Boundaries

Make dependencies directional

Each package owns one concern. A test rejects forbidden imports and cycles; source checks enforce named arguments and docstrings.

Inspect the checks {% include ".icons/material/arrow-right.svg" %}
05 / Observability

Leave evidence behind

Epoch records and run history retain metrics, seeds, the Git revision, machine context, and the run's whole config. log_elapsed times setup phases in the terminal; local plots and probes help explain the numbers.
